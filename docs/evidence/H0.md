## H0.2 — Journal durability & lifecycle recovery

**Red phase (recorded):** `crates/sniper-runtime/tests/journal_durability.rs` — initial run failed on missing `AlreadyLocked`/`SequenceGap`/`ChecksumMismatch` variants.

**Fixes (journal.rs):**
- `append()` now `writeln + flush + sync_all` — write-ahead durability by default (doc: record on disk BEFORE the stage it describes takes effect externally).
- Single-writer: O_EXCL PID lockfile at `<journal>.lock`; second live opener → typed `AlreadyLocked{pid}`; dead-owner lock reclaimed via `/proc` PID probe (fail-closed on probe failure).
- Per-record `checksum: u64` (DefaultHasher over seq+stage+intent+payload); `load()`/`open()` verify every checksum → `ChecksumMismatch{seq}`.
- Sequence contiguity validated (each record = prev+1; first arbitrary) → `SequenceGap{expected,found}`.
- Mid-file corrupted line = loud `Decode` error (never silently skipped). Crash-tail = ONLY a final line lacking `\n`, repaired at open by durable truncation to last complete record, surfaced via `tail_was_repaired()`.
- Fault-injection matrix: truncation at every boundary of a 5-record journal (cut=0..5) recovers exactly `cut` records; corruption at line 3/5 → error; post-repair append clean (no merged corrupt line).

**Fixes (lifecycle.rs):**
- `recover()` consumes `tail_was_repaired()`: any non-cleanly-terminal order escalates to `Unknown`.
- **Failed-after-Observed contradiction rule:** a journaled `Failed` recorded after an `Observed` restores as `Reconciling` (an observed-then-failed outcome only reconciliation resolves); plain reconciled-Failed stays terminal.
- `tail_was_repaired()` surfaced on `LifecycleMachine`.

**Tests:** 8 durability integration tests + 3 new recovery tests + 3 journal unit tests; legacy M1 test updated to single-writer contract (it opened two live machines — now correctly blocked).
