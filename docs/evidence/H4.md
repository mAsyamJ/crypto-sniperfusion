# H4 Evidence — Improvement Harness CLI Skeleton

Branch: `codex/harness-m3c-security` (H2 `f38f1cc`). Date: 2026-11-02.

## Deliverable

`harness/snf-harness` (python3 stdlib, executable, ~350 lines):
`doctor | verify | replay | fork | shadow | evaluate | compare | promote`
plus `selftest`. Every execution writes an IMMUTABLE run manifest to
`harness/runs/` (gitignored) recording: git SHA, argv, exit codes, input
file SHA-256s, timestamps (UTC stamp + unix), output digests, and the
`LIVE_TRADING_ENABLED` state at run time. Manifests are chmod 0444 and the
writer refuses to overwrite an existing id (`selftest` proves the
overwrite is rejected).

## Safety properties (demonstrated, not claimed)

- **`promote` NEVER enables live trading.** It only records that the paper
  configuration's gate chain passed. Live trading remains behind the
  independent operator-authorization path (config/risk/capability gates).
- **The shadow gate cannot be shortcut.** `shadow` is an honest stub
  returning `status: NOT_STARTED`, exit 3, with the ≥7-day-window reason —
  H3's observation window cannot be fabricated by the harness.
- **Promotion refused even with verify+evaluate green** (live run below):
  without a COMPLETE shadow window the decision is NOT_PROMOTED.

## Honest gaps

- `compare` pairs two evaluate manifests (delta of headline metrics);
  statistical significance/uncertainty fields are placeholders — real
  signal statistics arrive with H3 data.
- `replay`/`fork` wrap the existing sniper CLI and `start_fork.sh`; they
  are thin, proven-in-other-evidence layers.
- `verify` runs the full gates sequentially (~4 min on this host); no
  parallelization or caching.
- H3 shadow runner itself is future work (see PROJECT_STATUS).
